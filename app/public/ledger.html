    How to read this ledger

    Four rules decide what appears here and what each row can prove.

    Canonical records

    The API projects the tables that own each state change; it does not copy them into a second ledger.

    Receipt beats status

    A settled Solana row links its full signature to Solana Explorer. Pending rows explicitly have no on-chain receipt.

    No payout-key custody

    Payout keys stay on owner devices. An optional World deposit checkout may hold one encrypted per-purchase key only until its sweep; this ledger never exposes it.

    Historical reconciliation

    A bounded read-only scan walks known public system wallets back to their oldest available Solana receipt. Personal member-wallet histories are never scanned.

    What the numbers mean

    USD is an estimate.SOL rows use the current public spot quote, not the exchange rate at transaction time. Recorded USD advertising receipts remain exact fiat amounts.

    Expected expenses are estimates.When a vendor billed in consecutive months and a later month has no recorded receipt, the ledger shows that month's expected charge, sized from the last recorded month. It stays out of every total until the receipt is recorded.

    Plans are not payments.A prepared, approved, queued, expired, or rejected row can document an allocation or intent. Only a linked transaction ID is an on-chain receipt.

    One transaction can have many rows.A distribution transaction may pay several recipients. Each transfer is listed separately with the same transaction ID so its recipient and purpose stay visible.

    Earlier receipts are reconciled.The background backfill scans only configured community-pool, temporary World deposit, and retained legacy system addresses. It records finalized SOL transfers and suppresses duplicates already owned by a canonical ForkMesh record.

    Public subjects only.Links identify public accounts, wallets, repositories, issues, pull requests, claims, World elements, and accounting references. Private repository details are never published here. Billing providers keep their own invoices and payment methods; ForkMesh membership authorization is not presented as a payment receipt.
