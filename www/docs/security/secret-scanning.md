# Secret scanning before replication

A node copies every object it receives to mirrors, forks, clones and backups,
so **a pushed object cannot be recalled**. The only remediation for a leaked
credential is rotation; the only prevention is stopping it before the first
remote receives it. Every boundary prints this warning with its findings.

## Scanner contract

`tools/secret_gate.py` defines `forkmesh-secret-scan-v1` (standard library
only; `python3 tools/secret_gate.py contract` prints it):

- **Rules**: provider-prefixed token patterns (Git hosts, cloud providers, chat
  and payment services, AI APIs, package registries, PEM private keys) plus a
  generic password/token assignment rule, each with rotation guidance.
- **Placeholder filter**: the generic rule skips obvious placeholders
  (`example`, `changeme`, `${VAR}`, `{{ }}`).
- **Ignore marker**: `forkmesh-secret-scan:ignore-line` on a logical line skips
  it, unless the organization refuses markers.
- **Value-free findings**: rule, path, line, blob id and a fingerprint derived
  from rule, path and blob id, never from the value.

The desktop scanner carries the same patterns; `app/tests/test_secret_gate.py`
fails if they drift.

## Boundaries

| Boundary | Behaviour | Mechanism |
| --- | --- | --- |
| Local commit | Blocks or warns on added lines | `secret_gate.py install-hooks` (pre-commit) |
| Local push | Blocks or warns on every outgoing object | `secret_gate.py install-hooks` (pre-push) |
| Desktop push and review diffs | Review dialog or banner per match | desktop `RepoSecurity` |
| Node receipt (HTTPS and SSH) | Refuses the push before storing anything | `secrets` in the [node operator policy](../operations/node-operator-policy.md) |
| Sync and mirror intake | Detects after replication, quarantines under `block` | `node_operator_policy.py enforce` |
| Public security report | Findings without values | `tools/security_scan.py` |

```sh
python3 tools/secret_gate.py install-hooks --repo . \
  --repository owner/app --org-policy ~/.config/forkmesh/secret-policy.json
```

The installer never overwrites a hook it did not write.

## Policy

With no policy every rule blocks. The organization policy file:

```json
{
  "schemaVersion": 1,
  "mode": "block",
  "rules": {"generic-secret-assignment": "warn"},
  "customRules": [
    {"id": "custom-deploy-key", "title": "Deploy key",
     "pattern": "deploy_live_[A-Za-z0-9]{32}", "severity": "critical",
     "action": "block", "rotation": "Revoke it in the provider console."}
  ],
  "allowlist": [
    {"paths": ["tests/fixtures/fake/*"], "rules": ["*"],
     "reason": "synthetic credentials for parser tests"}
  ],
  "honorIgnoreMarkers": true,
  "allowRepositoryAllowlist": false,
  "allowRepositoryCustomRules": false,
  "overrides": {
    "allowedSignersPath": "/etc/forkmesh/secret-override-signers",
    "maxLifetimeDays": 90
  }
}
```

- `mode` and `rules` take `off`, `warn` or `block`.
- A repository's `.forkmesh/secret-scan.json` can only tighten rules; its
  allowlist and custom rules count only when the organization allows them.
  Deleting it in a push loosens nothing.
- Allowlist entries need a reason and cannot cover every path. Invalid or
  empty-matching patterns and unknown fields are refused.

## Signed overrides

A block is lifted only by an SSH-signed override naming exact fingerprints:

```sh
python3 tools/secret_gate.py sign-override --key ~/.ssh/id_ed25519 \
  --signer signer@example.com --repository owner/app --days 30 \
  --reason "synthetic token for a parser test" \
  --fingerprint <fingerprint> > .forkmesh/secret-overrides/parser.json
```

Signers are listed in OpenSSH allowed-signers format with
`namespaces="forkmesh-secret-override"`. An override is ignored if the
signature fails, it names another repository, it has expired or exceeds
`maxLifetimeDays`, or the policy has no `allowedSignersPath`. Accepted
overrides are written to the node audit log.

## Accuracy

`conformance/secrets/v1/corpus.json` (generated by `build_corpus.py`, all
credentials synthetic) is run by `python3 tools/secret_gate.py corpus` at every
boundary. Bounds: at most 15% false negatives and 10% false positives. Known
misses are JSON object keys, concatenated tokens and base64-wrapped keys.

## Response after replication

`python3 tools/secret_gate.py respond --report <scan.json>` prints the plan:

1. **Contain**: quarantine on nodes you operate, remove the value in a new
   commit, pause automation using it.
2. **Rotate** at the issuer and review its audit log.
3. **Notify** the owner and security contact with the value-free evidence.
4. **Residual risk**: existing copies keep the object; treat it as compromised.

## Telemetry and limits

Scan reports and `node_operator_policy.py status` count blocked, warned,
overridden, allowlisted and stored detections without values. Blobs over 1 MiB
and binary blobs are skipped and counted. Browser uploads and provider imports
are scanned only when they reach a node's `enforce`.
