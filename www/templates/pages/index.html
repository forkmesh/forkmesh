Health-aware routing

Mainnodes select an eligible, healthy, integrity-matching mirror when one is available; network distance is not promised.

Operator-held custody

The relay is not the canonical Git store and never asks for a wallet’s private key; mirror operators still control their own serving hosts.

Non-custodial: ForkMesh never stores community members’ wallet private keys or controls user funds. Reward states stay distinct — user-owned funds, community-funded pool, and on-chain pending / finalized results. Community incentives are not investments.

      ForkMesh FAQ

      Answers about desktop nodes, mainnodes, local Git mirrors, signed collaboration, encrypted repo rooms, and how ForkMesh keeps source code portable.

      What is ForkMesh?⌄

      ForkMesh is local-first infrastructure for preserving and collaborating on source code. Desktop nodes keep encrypted Git mirrors locally, while mainnodes coordinate discovery, direct-HTTPS clone routing, encrypted repo rooms, signed inboxes, and account lookup.

      Is ForkMesh replacing GitHub or GitLab?⌄

      No. ForkMesh works with Git instead of replacing it. The goal is to make repositories more portable and resilient, so important code can stay discoverable and cloneable even if one platform, account, or organization disappears.

      Where is the Git data stored?⌄

      Git mirrors live on independently operated mirror hosts: servers people run themselves or ForkMesh-managed hosts. Mainnodes coordinate the network, but they are not the canonical storage layer for Git objects. When someone clones a public repository through ForkMesh, a healthy, integrity-verified mirror serves it under the original URL.

      What is a desktop node?⌄

      A desktop node is the local ForkMesh app for working with repositories and managing the mirror hosts that serve them. It is a client, not a repository server: mirror hosts serve clone and browse data through ordinary HTTPS, and World and chat connections carry no repository bytes.

      What is a mainnode?⌄

      A mainnode is a coordination node for the ForkMesh network. It handles catalog discovery, account lookup, healthy HTTPS mirror routing, encrypted repo rooms, signed inboxes, and routing without becoming the owner of everyone's source code.

      How does collaboration work?⌄

      ForkMesh uses portable collaboration records such as signed issue events and signed patch PRs. Instead of locking all project activity inside one service database, collaboration can move with the repository and be verified by clients.

      Are repo rooms encrypted?⌄

      Yes. Public channels use controller-readable authenticated encryption so ForkBot, MCP, and webhooks can participate. Private channels and direct messages automatically add device-to-device encryption beyond the controller key. At most 500 persisted frames per room are retained for 7 days.

      Do I need to run a mainnode to use ForkMesh?⌄

      No. Most users can start by running a desktop node and mirroring repositories they care about. Communities, teams, or operators can run mainnodes when they want to coordinate their own catalog, routes, rooms, and inboxes.

      Who is ForkMesh for?⌄

      ForkMesh is for maintainers, open-source communities, researchers, archivists, and teams that care about keeping source code available long term. If a repository matters, ForkMesh gives people a way to help preserve it.

      Can ForkMesh preserve a repository if the original host goes offline?⌄

      Yes, if the repository has already been mirrored to other hosts. ForkMesh is designed so Git history can remain available through its mirrors instead of depending on one hosted forge staying online.

      Does ForkMesh store my repositories in the cloud?⌄

      ForkMesh does not make the relay or a mainnode the canonical Git storage layer. Git mirrors live on mirror hosts, whether you run them yourself or use ForkMesh-managed hosts. Mainnodes coordinate discovery, routing, rooms, inboxes, and lookup.

      How is ForkMesh different from a normal Git backup?⌄

      A normal backup protects one copy. ForkMesh adds network discovery, direct-HTTPS clone routing, signed collaboration records, encrypted repo rooms, and mainnode coordination so preserved repositories can still be found and used by others.

      Can open-source communities run their own ForkMesh network?⌄

      Yes. Communities can run mainnodes for their own catalog, direct-HTTPS routing, encrypted rooms, inboxes, and account lookup while contributors run desktop nodes that keep encrypted repository mirrors locally.
