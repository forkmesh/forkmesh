ForkMesh gives your agents context

A coding agent is only as good as what it knows when it starts. On ForkMesh, the things it needs to know (the issue, the discussion around it, how your team works, what was tried last time) live in the repository next to the code, and every run starts from them.

October 19, 2026AI agents4 min read

The picture at the top is all of ForkMesh drawn as one tree. Git and the mirrors are the roots: they hold the code and keep it reachable. The core servers are the trunk. The branches are everything you use: the desktop app, the web dashboard, the iPhone and Android apps, World, the Marketplace, runners, and the issues, pull requests and reviews your team writes. Agents sit on the same branches as everything else, so they can reach all of it.

The conversation lives with the code

On most forges an issue lives in the host's database, and an agent sees whatever you remember to paste into the prompt. On ForkMesh, issues and their comments are signed files under .forkmesh/issues/ in the repository itself, as Everything lives in Git explains.

So when you assign an issue to an agent, the agent gets the whole thread, not a one-line summary:

  • the title and the full description;
  • every comment, with who wrote it, in order;
  • the labels and assignees;
  • when you resume a run, the end of the previous session's transcript, so it picks up where it stopped.

How your team works, written down once

The rest of an agent's context is the kind of thing a new teammate learns in their first week. ForkMesh keeps it in the repository too, as plain files you can review like any other change:

  • Custom instructions replace the built-in preamble with your own rules.
  • Skills in .forkmesh/skills/ teach agents how a part of your project works. They can be set for one repository, for an organization or for the whole app.
  • Shortcuts in .forkmesh/shortcuts/ are reusable task prompts, such as the one that writes this blog's product updates.
  • Special agents (in beta, introduced in A team around the work) are files in .forkmesh/teammates/. Each one holds a role, instructions, skills and a linked shortcut, and knows the other special agents so it can hand work to them by name. A special agent that learns from its runs carries its earlier lessons into the next one.

Tools that reach the rest of the mesh

A good prompt is a starting point; sometimes an agent needs to look things up as it goes. Claude Code on the desktop gets ForkMesh's own MCP server, which lets it search code, read and update issues and plans, work with pull requests and tasks, and read chat. Codex and runner jobs get the issue context and your instructions, but not these tools yet.

The same context wherever the agent runs

Because the context is in the repository, it goes wherever the repository goes:

  • On your desktop, each run gets its own worktree, so parallel agents never step on each other.
  • On a runner, the agent takes a signed job lease, works in a sandbox, and can only push to its own agent/ branch.
  • From your phone, you can queue a run, follow it live and send follow-ups, as described in Runs that listen, branches that let go.

Claude Code and Codex are both supported. Whichever one you choose, the agent's work comes back as an ordinary Git branch you can review, merge or throw away.

Context that outlives any one host

Every copy of a ForkMesh repository counts. Any node can mirror a public repository, and clones are served from a live, signed, checked mirror, so the repository stays reachable when its original host goes offline. Since the issues, instructions and special agents are part of the repository, a mirror or a fork carries them along with the code. Clone it, and your agent starts with the whole story instead of a blank page.

Try it

Install the desktop app, open an issue in one of your repositories and hand it to an agent. Then add a skill or a few lines of custom instructions and watch the next run use them. If something is missing from what your agents see, open an issue on forkmesh/forkmesh or tell us in the ForkMesh Discord. Thanks for reading.
