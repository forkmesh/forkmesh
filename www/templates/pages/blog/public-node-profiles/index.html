Public node profiles

Registered nodes can publish a generalized profile, public repositories, and operator-approved status fields.

Feature 62 of 72FeatureAccounts, money & rewards3 min read

Why it matters

Public node profiles give registered operators a place to publish identity and public-repository context. Private repositories and fields disabled by the operator are excluded.

Preservation costs time, disk, bandwidth, and maintenance, so incentives need to point at the nodes and people doing the work. In ForkMesh, public node profiles addresses that need at the feature level, keeping the behavior close to the repository instead of buried in a detached hosted layer.

How ForkMesh handles it

ForkMesh handles public node profiles through the same split it uses across the product: ForkMesh links node identity, repository activity, public profiles, and Solana payment flows without changing Git ownership.

The behavior is intentionally narrow: profiles show the public identity key and only allowed repository, version, platform, status, and activity fields. A profile or online indicator is not evidence that a node is trustworthy.

Where it fits

Use public node profiles when identity, support, and incentives should follow verifiable node and repository activity.

It pairs with the rest of Accounts, money & rewards because Public node profiles keeps public identity and repository context for each node connected to the repository, its signatures, and the nodes that serve it.
