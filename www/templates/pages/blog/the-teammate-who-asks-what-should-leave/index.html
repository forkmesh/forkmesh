Product update

The teammate who asks what should leave

Meet Reaper: a repository-backed teammate that can make one evidence-backed case for retiring a feature—and cannot remove it. Around that guardrail, current main makes the team easier to evaluate, the mesh harder to misread, and optional tools easier to keep optional.

August 25, 2026Product update9 min read

A wider door, a clearer trail followed the route from migration to signed package to verified receipt. This update looks at the discipline around that route: who questions a feature's place, who may act, what evidence survives, and how the system behaves when a model, network, sampler, or mirror stops cooperating.

This update covers the work that landed on main from August 22 through August 25. No later desktop tag landed: v0.7.29 remains the newest signed desktop release. The work below is merged on current main; independently deployed App, website, and World surfaces can move on different schedules.

Meet Reaper, the teammate that argues for less

Reaper is a persistent teammate with one deliberately narrow job: identify the single product feature that no longer earns what it costs and file the retirement case. “Feature” is concrete here—a panel, menu action, setting, flag, command, endpoint, packaged extension, or documented capability. Dead helpers and unused dependencies still belong to Steward; defects belong to Quality; runtime costs in Qt code that is staying belong to Tempo.

Its definition lives in .forkmesh/teammates/reaper.json, with a weekly schedule and a linked propose-feature-removal.md shortcut. Reaper can read repositories and manage issues. It cannot delete code, open a branch, submit a pull request, close somebody else's issue, or make the retirement decision. It proposes; the owner or CEO decides; an engineering teammate performs any approved removal.

That boundary is already useful marketing truth. “AI feature pruning” could imply an autonomous cleanup pass. ForkMesh ships the opposite contract: a durable role, reviewable instructions, the least authority needed to present a case, and a human decision at the end. At the audited commit, Reaper's lastRunAtMs and lastSessionId are still zero. The teammate and schedule exist on main, but there is no claimed first nomination yet.

The case has to survive its own cross-examination

Each run starts by comparing the promises in the README and docs with the actual surfaces behind them. It then cross-reads issues and discussions for demand, Git history for neglect or unfinished work, tests and application logs for exercised behavior, and local ActionTelemetry records for actions that ran on that node. Dates and counts matter more than impressions.

The shortcut tells Reaper to attack its own evidence. “Nothing calls it” is not enough until dynamic invocation, named signals, generated code, resources, scripts, packaging, workflows, settings, migrations, wire formats, extensions, and public routes have been checked. One machine's telemetry describes one operator, not the fleet. A young, unannounced feature is unfinished rather than dead. Security, privacy, reliability, accessibility, observability, audit, ledger, migration, and compatibility paths do not become candidates just because a happy path rarely touches them.

Reaper nominates exactly one feature or none. A no-nomination run names the two closest candidates and the missing evidence that would settle them. A positive case must describe keeping cost, breakage, deprecation and data paths, compatibility, actual savings, alternatives short of removal, confidence, and evidence that would change the verdict. The issue is the argument, not a deletion ticket with a conclusion baked in.

Optional tools move out of the base product

A nearby change demonstrates the shape of careful pruning, but it was not Reaper's work: the runtime markers show Reaper had not run. The VS Code-compatible extension left the base extensions/ tree and reappeared as the opt-in ForkMesh for VS Code Marketplace package. Its manifest declares the issue-reading, process-launch, handoff-file, and Claude-extension permissions; install.default is false; the base desktop neither installs nor activates it.

The current Marketplace host does not yet install VSIX files, so this is catalogued source with a manual development build path, not a claim that clicking Install provisions an editor. The old desktop handoff listener is gone from the base app, while the package retains the compatibility protocol in its own source. The feature post and docs now say that plainly. This is a move from “part of ForkMesh” to “available beside ForkMesh,” with the runtime boundary visible.

The same package line gained smaller, practical improvements. Capture can paste a clipboard image as a movable, resizable annotation layer. Public Market listings can show current package previews, while the desktop separates All and Installed packages with real local counts. A new Settings → Apps surface tests the local developer tools ForkMesh can use and prepares platform-specific install commands only when the user asks. These are current-main capabilities, not adoption claims.

The team gets feedback and a fallback

Reaper joins another new repository-defined role: an operations-focused COO that turns agreed priorities into owned, sequenced work without gaining merge, release, or spending authority. The desktop Team surface has been tightened around these roles, with the roster moved into its own sidebar, table-like rows, clearer status, and direct paths between an issue, its branch, and the teammate run handling it.

Finished teammate sessions can now receive an operator grade from one to five. The grade stays on that local session and feeds the Team performance view; it is not a public quality score. A separate skill chart reads the skills captured when each run started, so editing a teammate later does not rewrite its history. Together, those two signals answer more useful questions than a raw run count: what the teammate was equipped to do, and whether the operator thought the result met the task.

Teammates can also carry an ordered list of backup model routes. Failover is intentionally narrow: it activates only when the active provider explicitly reports exhausted credits, quota, or a billing limit—not for an arbitrary error. ForkMesh keeps the assignment on its current branch, records the handoff, and queues the same session on the next configured route. When a question card outlives the process that asked it, answering the card now resumes or restarts the session with that answer instead of leaving the work stranded in Waiting.

Authority gets narrower while work gets easier to claim

Public contributors can assign themselves to an issue without receiving maintainer authority. A new signed claim event names exactly one account and whether it is joining or leaving; the relay accepts it only when the signed-in account is the account named. Every browser, desktop, and Go projection folds that event as a delta, so claiming an issue cannot replace or silently remove the rest of the assignee list.

Organization work now has a fuller desktop path. Owners and admins can manage members, teams, permissions, and organization-backed repository links through per-operation signed proofs. Organization-private tasks carry private replies, assignee avatars, undo, QA return, and a control for deleting closed tasks. Repository owners can explicitly waive pull-request review, while merge certificates, one-hour velocity, branch health, and All/Archived pull views make the consequence of that choice easier to inspect.

Agents gained two deliberately bounded doors into the project. The MCP helper can read bounded text and search tracked Git objects, create signed repository or personal notes, and use one fixed public chat room; it exposes no shell, arbitrary filesystem, room keys, credentials, or administration. A separate rate-limited guestbook lets an unauthenticated visiting agent leave an ordinary public note in #general. Its destination is fixed, the optional user's name is returned only as a greeting for the agent to relay, and agent names are self-described rather than identity proofs.

Unknown is no longer painted red

The public status model now separates an observed service failure from a monitoring gap. Missing sampler minutes remain neutral, appear as coverage gaps, and stay out of uptime math; recorded failures remain red. Sampling claims prevent duplicate folds, later compaction backfills missing history, and a delayed sampler says that it is behind instead of turning every component into a synthetic outage. A new flagship failure also waits for an independent retry unless visitor-observed evidence already confirms it.

Mirror recovery follows the same rule. A deployed flagship revision can be pinned into the accepted set, and the routing state can self-heal toward it when catalogs recover. The Go node can construct a deterministic merge only for tightly bounded issue-intake divergence—at least one side must contain complete new issue directories, and conflicting ordinary changes still stop. Healthy repositories remain servable through a transient refresh failure rather than being replaced by an empty or partial state.

On the desktop, a real offline mode stops non-loopback network requests locally while leaving local repositories available. An explicit reachability probe can bring automatic offline mode back online; the control is separate from taking a mirror node offline. Background Git and network reads continue moving off the UI thread, stale worktree locks can be recovered or cleared with an explicit action, and a visible countdown now precedes a requested restart.

A payment carries the work beside the receipt

Ledger now supports a direct work payment as well as a general member tip. The sender's desktop signs and broadcasts from its own linked wallet. The notice binds the recipient, exact amount, chain signature, task description, output link, and recorded conversion; ForkMesh writes the public work receipt only after the finalized Solana transfer matches. A pending transaction remains pending, and a mismatch writes nothing.

The public Ledger adds a Paid view, while the desktop can autocomplete ForkMesh recipients and show Discord names for pending reporter rewards when that is the identity the queue actually knows. Reporter-credit projections now build from D1 rather than a checked-in generated file. A tip-recipient board ranks finalized mainnet tip receipts, not estimates or unverified notices. These additions make payment state easier to follow without changing the custody model: keys and transfers remain with users.

What to inspect now

Reaper, teammate grading, model failover, the optional IDE package move, offline mode, the newer status and mirror recovery, and work payments are current-main work. They are not in the unchanged v0.7.29 signed desktop. The repository-native pull ledger did not add a merged pull record in this window; the audit instead follows the commits that reached main, their executable tests, closed issue records, manifests, and documentation.

Read Reaper's durable teammate definition and the full retirement-case shortcut. Browse the package catalog to see how the IDE plugin declares its optional boundary, or watch the desktop release page for the first signed artifact that contains this work.
