Why it matters

Live usage meter gives ForkMesh a concrete mechanism for agent runway displayed where assignment and review happen. See your Claude 5-hour and weekly usage right in the app, so you know how much agent runway is left.

AI coding only helps when the agent can work in a real repository without trampling human state or hiding what it did. In ForkMesh, live usage meter addresses that need at the feature level, keeping the behavior close to the repository instead of buried in a detached hosted layer.

How ForkMesh handles it

ForkMesh handles live usage meter through the same split it uses across the product: ForkMesh runs agents beside the repository, capturing transcripts, branches, diffs, prompts, usage, questions, and handoffs in the desktop app.

The behavior is intentionally narrow: See your Claude 5-hour and weekly usage right in the app, so you know how much agent runway is left. Humans keep control of instructions, answers, review, and merge decisions.

Where it fits

Use live usage meter when agent work should be reviewable, resumable, and connected to the same repo UI humans use.

It pairs with the rest of AI agents, built in because Live usage meter keeps agent runway displayed where assignment and review happen connected to the repository, its signatures, and the nodes that serve it.
