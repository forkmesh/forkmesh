Product update

A wider door, a clearer trail

ForkMesh v0.7.29 opens a resumable path for complete projects, puts extensions behind a signed lifecycle, and makes the route from report to release easier to follow.

August 22, 2026Product update9 min read

A team around the work described a main-branch workbench: persistent teammates, embedded Discord, visible review progress, and clearer mirror authority. Four days later, more of the path around that work has become explicit. A repository can arrive with its collaboration history, an extension can declare what it needs and how it leaves, a workflow can show where it is, and a completed payment can point back to the work it settled.

This report follows repository history from the previous post on August 18 through August 22. The signed release record moved from v0.7.23 to v0.7.29 inside that window. Changes that landed after v0.7.29's build commit are called out as current-main work; the hosted App, website, and World still deploy on their own schedules.

The release line catches up

The latest signed manifest now names v0.7.29 and binds its checksums to one source revision. It lists a Linux x86_64 desktop binary, the AppDir bundle, and the native Linux mirror-node companion. That is a concrete change from the previous post, when the latest signed desktop was still v0.7.23 and much of the work existed only on main.

Version numbers alone are not the story, but the boundary matters. The first Market lifecycle, repository migrations, the stock-Git conformance contract, Cove file editing, multi-run Actions, issue planning work, Ledger, and the event-driven mirror path are all ancestors of the v0.7.29 build commit. Later changes—including per-step workflow progress, bounded terminal-style agent output, sending a failed Action to an agent, modular package build discovery, a startup and teardown crash guard, and the newest reward-credit repairs—remain main-only at publication time.

A repository can arrive with its history intact

ForkMesh now has a resumable migration path for GitHub, GitLab, and Codeberg. Starting an import creates a durable job after the initial repository lookup; transfer continues in provider-sized pages, and an interrupted or rate-limited job resumes from its checkpoint. Public imports can resume without a credential. A private import asks for a current read token again because provider tokens are request-scoped and are not written into the job, its report, logs, or browser storage.

The contract covers more than a repository card. It preserves branches and tags, issues, pull or merge requests, reviews and inline discussion, releases, the provider README, labels, users, and exposed collaboration history. Original provider payloads are encrypted beside a common projection, while deterministic object keys make a repeated page an update instead of a duplicate. Completion sorts the surviving object hashes into a reproducible state digest and authenticates it with the relay's migration key. Git objects still travel through the normal bare-mirror path; provider wikis, workflow logs, and artifact bytes are named as separate or out of scope rather than silently omitted.

The browser can also request a fork onto one of the account's managed mirrors. The relay durably records the job, and the target node drains it when it is online, so clicking Fork does not require both source and destination to be awake at that moment. This is an asynchronous managed-node path, not a promise that ForkMesh can mutate an arbitrary external repository.

Normal Git gets a published contract

A generated compatibility matrix now says exactly what an unmodified Git client can do. Direct owner SSH is the write path: clone, fetch, branch updates, deletes, and force-with-lease are covered there. The stable relay HTTPS URL remains read-only and streams clone and fetch from an integrity-matching mirror. Shallow clones are covered; partial clones are conditional on protocol v2 and filter support; submodules keep their own authorization boundaries. The matrix publishes the limits beside the supported rows instead of compressing all of that into “Git compatible.”

The repository's live pull ledger supplied one especially useful proof. Pull request #32 merged after the previous post and restored builds against the declared Qt 6.4 minimum by replacing newer-only list, colour-scheme, and time-zone APIs with guarded or compatible forms. Its record includes the contributor's verification on Qt 6.4.2 and keeps the reward at pending_wallet; merged code and money that has not moved are different states.

A separate forkmesh-collaboration-event-v1 protocol and cross-runtime conformance suite also landed. It defines canonical signed envelopes, causal ordering, observed-remove sets, tombstones, moderation lineage, migration provenance, and replay defense across ten collaboration object families. That is protocol groundwork with executable reference folds—not a claim that every existing collaboration record has already migrated to the new envelope.

The Market becomes a lifecycle

The catalog now carries seven packages: Capture, Ledger, the X and Reddit World boards, Discord, Gemma 4, and a Winamp-inspired desktop theme. Capture moves region capture and annotation out of the application core. Discord can be removed with its token, local cache, avatars, unread state, and sidebar group cleared. Ledger contributes its own rail and data policy. Gemma 4 is opt-in and declares the Ollama download, process, storage, and repository permissions it needs. The World boards own their scene entry points instead of remaining hardcoded scenery.

The useful part is the envelope around those examples. A package manifest names its creator, version, type, licence, price model, permissions, entry points, previews, dependencies, provenance, and reversible migrations. External .fmpkg archives must sign the canonical manifest and every file digest; bundled packages inherit the signed release bundle. Installation and licence state stay separate, and uninstall must stop package work, detach its contributions, revoke capabilities, and remove package-owned state without deleting a purchase receipt or user-created output.

v0.7.29 includes the first catalog and install/remove experience. Current main goes further by letting each package own its desktop build descriptor and World module declaration, so adding one no longer means editing a central source or resource allowlist. The public Market page is generated from the same catalog, but this post makes no adoption claim: download and install counters exist precisely so future decisions can use observed demand.

The workbench shows the work

Encrypted Coves now hold working files, not only conversation. Ten quick-create templates open in a shared file editor; CSV becomes an editable spreadsheet, and a pipeline document gets stage, lead, history, and report views without asking someone to edit raw JSON. Cove share links carry repository and cove identifiers but no encryption material. The ordinary Files surface and Cove Explorer use the same editor path, which reduces the gap between a private draft and a repository file.

Actions can watch several queued, running, or held runs side by side while keeping one full detail pane for approval, controls, and logs. Agent rows expose a one-click start or stop control, and issue comments can address a configured model with an @model mention: a question returns a signed comment in the thread, while a clear request to make a change starts an agent on that issue. Those behaviors are in v0.7.29.

The newest work is still on main. Workflow cards now show each step moving through queued, running, passed, failed, or cancelled state. Long agent command output stays in a scrolling terminal-sized viewport rather than stretching the transcript indefinitely. A failed Action can be handed to the default agent with the complete local run log, and the desktop preserves enough run state to recover interrupted workflows. These are merged and tested, but they are not in the v0.7.29 binary.

A report can become credited work

An optional, operator-configured Discord bug-channel watcher can now separate a report from chat, check it against existing issues and reachable source, copy bounded attachments, and place a reviewed draft in the repository's issue inbox. Filing does not wait for the working-copy node to be online. A linked Discord identity receives reporter attribution; an unlinked person is credited by the displayed Discord name, with no guessed account match. This is a configured bot-and-cron path, not a listener on every server or channel.

Once a report is inside ForkMesh, web and desktop issue views can turn Markdown checkboxes into interactive tasks and link a checklist item to a sub-issue. The web can close, reopen, or delete an issue through the repository-backed issue path, and notification preferences can choose queued instant email instead of a digest. Current main also projects maintainer-reviewed reporter credits onto profile contribution graphs without double-counting reports already signed by that person.

Mirrors move on events and keep their evidence

The mirror path now wakes on change. A successful push emits a repository-scoped event, mirrors refresh immediately, and the native node drains collaboration intake over its event socket in bounded pages. Reconnect still performs catch-up, so “event driven” does not mean “drop anything missed while offline.” The v0.7.29 release also carries the native mirror companion beside the desktop artifact.

Provisioning received a harder safety pass. The desktop creates a bare repository and seeds its local heads and tags directly, so a new node can receive content even while public routing is degraded. An empty refs digest cannot count as healthy, and nodes that already hold published data are kept while replacements come online.

If the working-copy source disappears long enough for its last pin to age out, two distinct group nodes must independently publish the same signed state before that newer state can be admitted. One node is still only one claim, disagreement is not quorum, and a live source is never overridden. The recovery route widens the evidence only when the original authority is genuinely absent.

The Ledger closes a loop without taking custody

Ledger is now an in-app Market package rather than only a browser shortcut. It reads the public financial record and offers Send payment only when the ledger row and an owner-authored payout plan agree on the exact recipient and amount. The desktop signs one Solana transfer locally; ForkMesh marks the estimate paid only after verifying the finalized transfer, then writes the public transaction reference back to the issue or pull request it settled.

Personal expense and income rows, manually tracked addresses, wallet balances, and funding QR codes stay in that device's settings and are not published as ForkMesh ledger entries. The post-release main branch adds recovery for a finalized payment whose receipt could not reach the relay, keeps the notice queued instead of signing twice, and makes the transaction link explicit. Those fixes sharpen the distinction between money moving on-chain and ForkMesh successfully recording why it moved.

What to try now

v0.7.29 is the newest signed desktop release in the repository. Its source revision contains the first package catalog, resumable migrations, the published stock-Git contract, Cove file editors, multi-run Actions, issue planning and Discord intake, Ledger, and the event-driven mirror work described above. The explicitly labelled current-main desktop changes need a later signed release, and repository evidence alone does not prove that an independently deployed hosted surface is already serving its matching worker revision.

The audit used the complete main-branch diff, the live forkmesh/pulls ledger, closed issue records, signed release metadata, generated compatibility and protocol artifacts, and the operating documentation. It found one merged repository-native pull record in the window: the Qt 6.4 compatibility change above.

Get the current signed desktop, browse the package catalog, or read the exact stock Git compatibility matrix.
