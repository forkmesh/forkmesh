Product update

A team around the work

ForkMesh's current main branch is turning agent sessions, review panes, mirror records, and chat rooms into one steadier workbench—without blurring the line between merged code and a released desktop.

August 18, 2026Product update8 min read

Shorter loops, stronger proof followed work from a report through review, mirrors, and a public receipt. Since that post landed, the center of gravity has shifted toward the people—and agents—who keep those loops moving. Roles can now live with a repository, review progress stays visible, and another conversation system can meet the desktop where the code already is.

This is a current-main update. The newest signed desktop artifact remains v0.7.23, so the desktop work below is not being presented as something already available from the download page. App, website, server, and World changes can deploy on their own cadence; a merged commit is still not proof that a hosted surface is live.

Teammates move into the repository

A new Your Team beta surface gives each repository a roster of persistent AI teammates. A teammate has a name and specialty, a model, working instructions, selected skills, an optional repository shortcut, a human-readable schedule, and an explicit action boundary. The desktop shows who is working, queued, scheduled, or idle; a detail page keeps the current session, recent activity, linked capabilities, and permission choices together.

The durable definition is ordinary JSON under .forkmesh/teammates/, not an opaque hosted profile. That makes a role inspectable and reviewable with the rest of the project. Identity stays stable if the selected model changes, and removing a teammate leaves its prior agent sessions and branches intact. The repository now carries Quality and Marketing definitions, while the editor includes a Quality Assurance starting template for another project to adapt.

Work can start on demand, hourly, daily, weekly, on selected days, continuously when repository work appears, or on new issues, pull requests, assignments, and mentions. Automatic runs are opt-in and driven by the open desktop client, not a promise of hosted background execution. A teammate cannot start without repository-read access; a teammate without modify access starts in Plan mode; and opening a pull requires modify, branch, and pull-request permissions together. The rest of the boundary is written into every assignment. That is useful scope control, but it is not a new operating-system sandbox.

Review keeps a visible finish line

The desktop diff now opens with one narrow review bar: files viewed, total additions and deletions, the kinds of changes in the branch, and how many files remain. Each file row follows the same reading order as the Changes tree—status, file type, name, then directory—with exact churn beside the small change meter and a properly bounded Viewed control. The result is less decoding between the tree and the patch, especially after reviewed files collapse.

Branch history no longer means “since midnight.” The landing view starts with the last 24 hours and can widen to 7 days, 30 days, or 6 months; expensive churn totals stay bounded to the newest rows instead of pretending to summarize a window they only partly scanned. Pull refreshes also avoid overlapping work, and stall diagnostics now record more context without re-entering the interface while it is trying to recover.

Agent scheduling is more honest under pressure, too. If someone lowers the concurrent-agent limit below the number already running, newer sessions park at the front of the queue while preserving their CLI conversation and worktree. They resume as the longer-running sessions release slots. The purple activity fireball is only a status cue, but it now carries its phase forward as speed changes instead of jumping backward or resetting when a row redraws.

Discord can join the same workbench

Desktop Chat can now connect an optional Discord bot and place server text channels, active threads, and bot direct messages beside native ForkMesh conversations. Recent history and live messages use the existing transcript. Replies, typing, reactions, edits, deletes, avatars, and attachments follow the same interaction patterns, and a channel can still open in Discord when its native context is useful.

The bridge deliberately accepts bot credentials, not normal Discord user tokens. Discord's server permissions remain authoritative, and messages sent from ForkMesh appear under the bot's identity. The token stays in device-local app settings rather than action variables, process arguments, logs, or chat history; disconnecting removes it and the cached Discord conversations from that device. This is an integration with Discord's bot API, not a claim that the two systems share identity or storage.

Native channel creation became easier to find at the same time. The desktop now labels the channel list and gives New channel a real button. In the World Office, organization members—not only administrators—can open the existing channel-creation flow, with membership read from the authoritative organization record rather than inferred from team rows.

Repository surfaces trade ceremony for signal

The web repository list now shows up to 100 projects per page instead of five. Language, visibility, mirror state, update time, issues, commits, pulls, and discussions share one wrapping metadata row, so a larger mesh takes less paging and each card takes less vertical space. Repository pages use a full-width tab strip over a bounded content column, move Releases and Size map into direct actions in the About rail, and can show the faces behind fediverse watcher counts.

Issue, pull-request, and discussion rows are links again. A normal click still uses in-app navigation, while middle-click, modifier-click, and Copy link address work like they do elsewhere on the web. Repository art follows the same principle of showing real project state: a committed root logo.png or an owner-uploaded logo wins, and a project without either keeps the neutral repository icon instead of receiving a generated mark.

The Calendar work from the previous update also received its scaling pass. Web activity is fetched and cached by repository and month, rendered as each result arrives, and bucketed once per day. The desktop reads repository activity in timed slices after first paint. Gateway history now answers nested activity windows with one commit walk. These changes make the existing all-ref calendar practical on a repository with a long history; they do not introduce a new calendar data source.

Mirrors say where authority actually lives

A serving mirror is no longer promoted to “source of truth” merely because it is the freshest node online. The mirrors API and its public snapshot contract now name the logical working-copy authority separately, while the page lists independent serving nodes on their own terms. When a mirror advertises the same commit, the UI can use the canonical content size while still comparing that node's published counts; physical Git pack sizes may differ without implying different repository contents.

Several recovery edges reinforce that distinction. Retired nodes are filtered from current mirror results. A short catalog sweep merges the evidence it did observe instead of blanking node statistics it could not re-read. Deleted issue records remain in Git as audit history without inflating the visible open count. Organization aliases must hand off to another fresh mirror in the same signed repository group before their backing node can be retired.

Operational state is tightening around the same source-of-truth rule. The status page can confirm an accepted email against the mail provider's delivery record when a delivery callback never arrives, so a missing callback no longer reads as an indefinite outage while a real delivery failure is still reported. A same-browser App session can also restore in World through the revocable account cookie without putting a bearer token in a URL.

The release line has not moved

No desktop tag was added in this reporting window. v0.7.23 remains the newest signed desktop release; persistent teammates, the Discord bridge, the new review bar, branch windows, queue parking, and the later desktop fixes described here are current-main work. The teammate surface also labels itself Beta. Testing a source build is not the same thing as receiving a signed update.

There were no new merged repository-native pull records after the previous post's publication commit. The evidence here comes from the commits that reached main, their diffs and tests, the unchanged release record, the repository's issue and pull ledgers, and the updated operating and desktop documentation.

Watch the desktop release page for the next signed artifact, read the desktop and Discord guide, or check current service health.
