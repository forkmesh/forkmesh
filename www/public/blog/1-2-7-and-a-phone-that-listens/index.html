Product update

1.2.7, and a phone that listens

Desktop 1.2.7 is out, and Windows installs work again. Your phone can now start an agent in a terminal on your desktop, take a prompt by voice, and hold direct messages that leave our server once they're delivered. Task reminders also always reach the person you sent them to.

October 2, 2026Product update8 min read

This one covers a short stretch: from the evening of September 30, when the last update went out, to this afternoon. That's 295 merges into main and 357 commits. The headline is a desktop release we'd been promising for a week.

A note on what "live" means below. Every push to main that touches the website or the app deploys itself, and today's last change reached our servers at 3:20 this afternoon, so anything on the web is live now. Desktop and phone features are in your hands only once they're in a release. 1.2.7 was built from the code as it stood at 3:39 pm on October 1. Anything merged after that says "next release". The new iPhone app still isn't on the App Store, so iPhone features are only on our own test phones for now.

Desktop 1.2.7

Last time we said the next release would be 1.2.6. It wasn't, quite. 1.2.6 hit a Windows build error and lost its installer, so the only part of it we published was the mirror node. The desktop app never went out. 1.2.7 carries everything 1.2.6 was meant to, and went out on the latest channel on October 1. If you're on 1.2.5, this is your next update.

Here's what you get on each platform:

  • Windows: a clean install no longer stops with "Qt6OpenGLWidgets.dll was not found". The packager now reads every library the program imports, bundles all of them, and refuses to build an installer if any is missing. The installer is signed with our own certificate, not one from a commercial authority, so Windows will still say "Unknown publisher".
  • macOS: one universal .dmg for Apple Silicon and Intel. It's still ad-hoc signed and not notarized, so macOS will complain the first time you open it.
  • Linux: the binary and the AppImage, built the same way as 1.2.5, for Ubuntu 22.04 or newer and Debian 12 or newer.
  • Android: the first release of the native app, written in Kotlin and Compose. It replaces the old cross-platform APK. The signing key changed in September, so if Android won't install it over the app you have, uninstall the old one first. Uninstalling removes that app's data on that phone.
  • iPhone: nothing new in this release. More on that below.

There are also changes for every desktop platform. Update, rebuild & restart no longer deletes your checkout when a pull fails: it stops, tells you why, and changes nothing. Quitting the app now ends every process it started. Agents can open, read and screenshot desktop windows and browser pages through ForkMesh's MCP tools.

On Windows and macOS there's no in-app updater yet. To update, download the new installer or disk image from the homepage and install it. The release manifest is signed with an Ed25519 key, and the install script and the homepage download card both check it against a key built into them. Before writing this we checked 1.2.7's signature against that key ourselves, along with the checksum file it vouches for.

Start a desktop agent from your phone

Last week your phone learned to watch and type into Claude Code and Codex sessions running in a terminal on your desktop. Now it can start one too. Pick a repository the desktop has open and choose Claude Code or Codex. The desktop starts it in a terminal of its own, and the phone shows that terminal live, with Esc, Tab, the arrow keys and Ctrl-C as well as text. If you leave the screen, the agent keeps running, and it stays in the Agents list until its CLI exits. When you send a follow-up to an agent, you can also switch its model or mode.

Removing a phone from your account now also cuts off its control of your desktop through our relay right away. Before, a phone approved through your account kept that control even after you removed it. A phone you approved in person with the six-digit code is different: it stays approved until you remove it under Settings → Phone on the desktop. Away-from-home control also recovers by itself when a relayed connection dies.

All of that is in 1.2.7 and its Android app. Merged since, for the next release: managing the desktop's recycle bin from the phone (restore, delete for good, and how long things are kept); sorting the agent list by the desktop's run priority; "Stop all agents"; deleting an agent with a swipe; and image diffs. Images and SVGs show before and after, and the review marks a file as viewed when you scroll past it. On the web and in all the apps you can also pick which Claude or Codex account a cloud runner uses. The web picker is live now.

Saying it out loud

On iPhone, "Hey Siri, start a new agent in ForkMesh" opens the prompt, even if the app wasn't running. Siri could already stop, continue, message and merge agents by number ("Agent 754") or by part of their title. The new Siri guide lists every phrase, explains why each one has to name ForkMesh, and shows how to set up shorter phrases of your own. It's written for the native iPhone app, which isn't on the App Store yet.

When you open the prompt, it now starts listening straight away. A setting turns that off. On iOS 26 it uses Apple's newer on-device speech recognition, and nothing it hears is written to disk. On both iPhone and Android, a dictated prompt sends itself once you've been quiet for a moment, so you can talk to an agent without touching the screen. All of this is in iPhone test builds; the Android auto-send ships with the next APK.

Direct messages that don't stay

Direct messages now show up in the chat panel on every dashboard page, not just on the full chat page, and there's a button for starting a new one. "Add person" in a direct message creates a new private group with the three of you, and it tells you that before it does. Earlier messages can't come along, because they're encrypted to the two original devices.

Our relay now deletes its copy of a direct message as soon as the other person's device has it. The top of the conversation shows which state you're in: "1 message on the server" while a copy is waiting, "Not stored on the server" once it's gone. Some limits: "received" means received by one of their devices, so their other devices won't get that message later. Group channels are unchanged. A client that doesn't send receipts yet, including today's desktop app, leaves copies on the server for the usual seven days, and the count says so. This is live on the web. The desktop side ships next release.

On the full chat page, a direct message also has audio and video calls. The call setup is end-to-end encrypted, and the audio and video go straight from one browser to the other, so our relay doesn't keep any of it. It's a first version: the call only rings if the other person has that conversation open, and if you're both behind a strict home or office firewall it may not connect.

Pings that get through

When you press Remind on someone's task, it now always reaches them, even if they've muted mentions, paused pings or are in quiet hours. That's because a person asked them directly. The reminder also goes on the task's timeline, saying what happened: "ping sent, pushed to 2 phones", or that it couldn't be delivered. Once they open the task or read the ping, it shows when they saw it. The server side is live now. The desktop showing the reminder even while your pings are paused comes in the next release.

Pings that report a problem now come with a one-tap fix. A build that failed because the build Mac was off the network offers "Turn off this action", for example. The desktop learns which fixes you choose, and once a fix has proven itself it applies it on its own, tells you, and lets you undo. That's merged and needs the next desktop release. On the phones you can also clear every ping with one tap.

A busier CRM

The CRM package on the web got three new views. My queue is the contacts you own that are waiting on you or have a next step. Waiting on us is everyone whose last email came from them. Possible duplicates is contacts that look like the same person. You can also tag or reassign many contacts at once, connect Zoho Mail in one click, and see "Last contacted" in the default view. A pipeline can now be shared with people outside your organization, and they work it from their own dashboard. All of that is live. The iPhone and Android apps have caught up with the desktop CRM in code, but that isn't released yet.

Smaller things

  • Office calls now have a fallback for strict firewalls: when a direct connection can't form, the media goes through a relay on our own servers instead of failing.
  • The status page has one release row per platform (Linux, Windows, macOS and Android), so each platform can be released on its own schedule. Its email row also says why mail is being held back.
  • Sending a prompt to a paused desktop agent now lets it run (next release).
  • Unread badges now count up to 999+ instead of stopping at 99+. That's on the web now and in the apps from the next release.
  • Fewer failed requests while the app restarts during a deploy.
  • forkmesh.com now has an llms.txt that tells AI tools what's on the site.

Coming next

The next desktop release picks up everything marked "next release" above. The iPhone app still has a few steps before we can submit it to the App Store. We'll post here when it's out, not before. There are no dates for either yet.

If something here doesn't work the way we've described, open an issue on forkmesh/forkmesh. Thanks for reading.
