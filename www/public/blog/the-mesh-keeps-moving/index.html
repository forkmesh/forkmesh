Product update

The mesh keeps moving

ForkMesh's current main branch turns teammate runs into a shared, reviewable workbench, carries identity and mobile work further, and makes the mesh more candid about recovery when a signal is missing.

August 28, 2026Product update7 min read

The teammate who asks what should leave gave Reaper a narrow, evidence-backed job. This update follows what happened around that role: the rest of the team gained a shared run surface, sessions kept more of their history, identity got a portable recovery format, and the network learned to separate “we saw a failure” from “we did not get a sample.”

This update covers the work that landed on main from August 25 through August 28. The latest signed desktop remains v0.7.29; everything described below is current-main unless marked otherwise. App, website, World, and mobile surfaces can deploy on different schedules.

One team can now share one run

The desktop Team surface can run every available prompt-based teammate in one agent session. Each participant keeps its own assignment, but the session records the full teammate list, so attribution survives a restart and a shared run still has a durable home in the repository's agent history. Daily briefings use the same shape: one session can collect the team's configured work instead of scattering a single briefing across unrelated processes.

That shared run is paired with more deliberate controls. Agent sessions can be ranked with priorities from 1 through 99 and linked back to an organization task. Teammate run modes, persisted prompts, individual briefing refresh, and a self-improvement cycle give an operator a way to keep the loop moving without turning it into an unbounded automation claim. Outputs remain opt-in, and a teammate still needs the repository permissions its task requires.

The web can launch an agent for an eligible owner node, while the desktop keeps the branch, session, and review path visible. A failed or interrupted run has somewhere to resume, but that does not mean a hosted service is running every schedule in the background. The durable configuration lives in the repository; execution still depends on the available client, model route, and permissions.

Feedback has a place to land

The desktop now treats agent work as a conversation with a finish line. A session can point to its issue or organization task, its branch, its checks, and its next review action. Active agents sort ahead of completed history, the list can be reprioritized directly, and a task link opens the task that gave the run its scope. A small performance improvement also collapses duplicate Git reads during the merge sweep, keeping the view responsive as the history grows.

Pull and mirror intake received the same attention. The desktop drains all available issue mirror pages, preserves the upstream checkout boundary, propagates branch deletion, and keeps conflict fixes on the pull-request branch. Owners can explicitly waive pull review when their policy allows it; the interface shows the choice instead of implying that every repository follows one review rule. Those are workflow changes, not a new claim that every change is automatically safe to merge.

A private conversation has a narrower audience

Private channels and direct messages now add an automatic device-to-device encryption layer inside the room cipher. Each protected frame gets a fresh content key, wraps that key for known participant devices with X25519 and HKDF, and keeps the recipient ciphertext behind the outer room envelope. Browser, desktop, and mobile clients share the same v2 envelope fixture and reject a protected frame that does not validate.

The boundary is important. Public # channels stay controller-readable so ForkBot, MCP, and webhooks can participate. Device-key discovery is not authenticated membership: an actively modified controller could inject a key, and an operator serving modified browser JavaScript can read that browser's plaintext. Timing, sizes, connection metadata, and durable flags remain visible; the protocol is not a double ratchet and does not promise post-compromise security. The current security guide is the source of truth for those limits.

The same private-room work now gives team agent threads a protected place to live. The relay can still drop, delay, replay, or withhold frames, so this is a confidentiality boundary for protected conversations, not a promise of availability or perfect participant authentication.

Identity can move without becoming a hosting dependency

Portable identity export is now a documented, provider-neutral JSON format shared by web, mobile, and Qt desktop. The client encrypts the local payload with AES-256-GCM using a 600,000-round PBKDF2-HMAC-SHA-256 key derivation, canonical base64url fields, and authenticated data that binds the format version. The relay does not receive the passphrase or the plaintext container. Passkeys and hardware-key private material remains intentionally non-exportable.

That is a recovery kit, not a magic reset. The docs still require independent control of the passphrase, a fresh key on a replacement device, revocation of a lost device, and tested recovery drills. The broader identity epic remains a release-level outcome with more drills and delegation evidence still required; this shipped format is one concrete step, not a claim that every recovery path is complete.

The phone can participate, in the foreground

The mobile app now has the shape of an independent mobile node. A bound phone can sign and apply supported issue, pull, and discussion work through the account sync path, show node activity, and commit applicable items to a local repository. If a desktop node is enrolled, the phone stays in standby so two nodes do not drain the same inbox. Items it cannot honestly apply—such as work that needs a desktop working copy—remain available for the desktop rather than being acknowledged and lost.

The contract is deliberately smaller than “a desktop in your pocket.” Mobile nodes do not host or mirror repositories, do not run in the background, and do not touch wallet or mirror-process settings. Applied local commits still need an explicit push to publish. APNs registration and the next store build are groundwork in current main; repository evidence does not establish an App Store release.

Recovery should not manufacture an outage

Status history now makes monitoring coverage visible without painting missing minutes red. Recorded failures remain failures; an absent sampler is a coverage gap. Uptime calculations no longer turn a partially observed period into a perfect number, and an independent retry is required for a new flagship failure unless visitor evidence already confirms it.

Mirror proofs renew on a tighter cadence, status snapshots can republish as an atomic pair after a real transition, and the handoff path can recover toward a deployed flagship revision after catalog trouble. A healthy repository stays servable through a transient refresh failure instead of being replaced by an empty or partial state. The native node's deterministic merge remains intentionally narrow: bounded issue-intake divergence can converge when the required directory evidence is present; conflicting ordinary changes still stop for review.

These changes are unglamorous by design. They make the public status page, mirror router, and local diagnostics say less when the evidence is weak—and say it more clearly when the evidence is strong.

What is live, and what comes next

The repository's default homepage also now presents a clearer capabilities and plans surface, and the World gained adaptive device-quality groundwork. Those are merged website and World changes, but they remain subject to their own deployment and device validation. The current signed desktop download is still v0.7.29; the shared teammate runs, sealed private chat, portable identity, mobile-node work, and recovery refinements need a later signed artifact or their matching hosted rollout before they should be described as universally available.

The window contains closed issue records for identity recovery, release preservation, World rendering, issue filters, and navigation, but no new repository-native merged pull record. We treat those records as evidence of completed slices and verification work, not as proof that the larger roadmap epics are done. The next useful step is end-to-end validation across the clients and a signed release that carries the desktop portion of this work.

Get the current signed desktop, check the live status page, or browse the public documentation for the portable-identity and sealed-chat contracts.
