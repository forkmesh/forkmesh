Issue bounties

The earlier issue-bounty flow is retired. Funding and payouts are switched off, and historical records are read-only.

Feature 65 of 72FeatureAccounts, money & rewards3 min read

Why it matters

An earlier version of ForkMesh held issue-bounty deposits and paid them out automatically. That design does not fit ForkMesh’s non-custodial approach, so it is no longer an active funding or payout path.

How ForkMesh handles it

Bounty wallet creation, funding, and automatic payouts are switched off. The web, desktop, and mobile apps show historical bounty state as read-only, and no funds move automatically.

Any future issue incentive will use an owner-controlled external wallet, program, or multisig; publish only public transaction evidence; and verify exact finalized transfers. ForkMesh will not create or hold a custodial wallet for the issue or contributor.

Non-custodial notice: Do not send funds to a historical bounty address. ForkMesh does not hold or control user funds, and this retired bounty flow never asks for payout private keys, seed phrases, or mnemonics.

Where it fits

The current community reward program supports verified mirror-node incentives on Solana mainnet-beta; explicit development deployments may select a test network. It does not reactivate issue bounties.

Historical status labels are accounting and migration records, not user balances, redeemable claims, or guaranteed payouts.
