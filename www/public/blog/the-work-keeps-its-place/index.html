Product update

The work keeps its place

A hosted repository can now finish a web merge on its own cores. Runner work is easier to follow from the desktop. Phones carry more of a local repository, and the Office has started to remember the people and places around the work.

October 4, 2026Product update5 min read

This update covers the work merged on main from the afternoon of October 2 through October 4. The served stack is still catching up to the end of that window, and the desktop and native apps have their own release gates, so the notes below say when something is on the hosted service, on current main, or waiting for a release.

A hosted repository can carry the merge

A pull request in a public hosted repository can now finish where the repository lives: on one of ForkMesh's cores. The server performs a real non-fast-forward Git merge, records the result, and lets the other cores fetch it. If an agent's branch already lives on a mirror, the merge starts there first instead of making the branch travel somewhere else.

There is a small but important change behind that: publishing no longer waits for the repository cache to warm up. The new generation is registered first and warmed in the background, so a successful merge can return without holding the next branch operation in line. This is merged on main; the latest fleet manifest had not yet advanced to this reporting window when we wrote it.

Browser mirroring from GitHub, GitLab, or Codeberg works on the hosted ForkMesh service only. Paste a public HTTPS repository URL into the hosted service's New repository page and ForkMesh creates a real hosted, cloneable copy. The separate provider metadata import still brings over issues, pull requests, releases, and selected documents; it does not make the Git objects cloneable by itself. Self-hosted operators still use the desktop handoff and their own mirror setup.

From runner session to reviewed change

Cloud runner sessions now carry the parts of a branch that matter when you come back to them: the base branch, runner, file count, additions and removals, and merge state. The phone and web views can inspect the same branch diff and follow it through merge and cleanup. A session can continue after a runner changes, instead of treating the last lease as the only place it exists.

On the desktop, a cloud transcript now reads more like a local agent run. Bash calls fold into compact command rows with familiar icons, while the actual agent conversation stays visible. The web can also edit a repository file directly, and a branch diff can collect a comment from a line number even when no pull request exists yet. These changes are on current main and await the next desktop build where the client is involved.

The phone holds more of the repository

Android now keeps one local copy of each repository on the phone and can sync a clone forward with Git's fast-forward path. Packed objects are read on demand, and checkout writes only the files that changed. The phone clone path also stopped carrying its old small-size ceiling and uses a shallow first clone, which makes the local copy a more practical working surface. The code and tests are merged; the next Android release is the availability boundary.

On iOS, the Commits screen now has a lane graph with Desktop, Web, and Mobile markers, and branch review comments can travel through the pull inbox. The native iPhone app is still not in the App Store, so these are current-main native changes, not an App Store availability claim. The phone's Desktop screen also has clearer load and battery signals, with a power-loss alarm in the native clients.

The Office remembers the people in it

The shared Office has grown from a map into a more legible place to work. Profile cards can show a display name, local time, picture, status, room, and team; an avatar editor lets each member choose their look. The browser keeps your room and position after a refresh, so returning to the Office does not begin by dropping you somewhere random.

There are now quiet rooms, a Library, a Media Room, Lobby Couches, a Workspace, and a Focus Lounge. A couch can start a timed focus session, with an optional status and recent-session history. Desks can carry a small set of personal decorations. Applause is no longer a silent emoji: a clap animates, a celebration throws confetti, and a room can answer a shared moment with a short cheer. The Garden pond and Campfire give the Office somewhere to pause as well as somewhere to work.

Those changes are merged together with the Office's new release path, which means an Office-only change can now reach the served build. The current deployment still needs to pass its fleet health gate before we call the whole window live.

What follows

The next release boundary is deliberately visible: desktop changes stay in current main until a desktop build carries them, native iPhone work still needs App Store submission, and Android repository sync waits for its next APK. On the hosted side, the browser repository and merge work is ready on main while the fleet catches up.

Try ForkMesh in the browser to start the hosted workflow. If something here does not work the way we described it, open an issue on forkmesh/forkmesh. Thanks for reading.
