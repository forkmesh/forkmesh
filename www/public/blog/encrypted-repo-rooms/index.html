Encrypted repo rooms

Public repository rooms admit controller integrations; private channels add automatic device-to-device encryption. Up to 500 persisted frames remain for 7 days.

Feature 47 of 72Shared keyChat & private sharing3 min read

Why it matters

Encrypted repo rooms give ForkMesh a concrete mechanism for repo-scoped rooms encrypted before frames are sent. Public channels remain controller-readable for integrations, while private channels add automatic device-to-device encryption beyond the controller key.

Project conversations often carry design, access, and coordination context, so the UI makes that trust boundary explicit: Public admits controller integrations; End-to-end protects private conversation content from passive controller decryption.

How ForkMesh handles it

The Town Square compatibility room computes SHA-256(DATA_KEY + ":room-chat-passphrase-v1"). Every other repository computes SHA-256(DATA_KEY + ":room-chat-passphrase-v2:" + lower(owner + "/" + repo)), so a public-room key cannot decrypt a private-repository room. The relay releases that scoped passphrase only to an authenticated account or signed node authorized for the repository. Clients apply PBKDF2-HMAC-SHA256 for 210,000 rounds with the first 16 bytes of SHA-256("ForkMesh room:" + roomName), then encrypt frames with AES-256-GCM.

Only frames marked for persistence enter history. The relay keeps the newest 500 persisted frames per room for no more than 7 days; oversized frames are relayed but not retained. Private frames carry a recipient-sealed inner envelope, so the relay-derived key alone cannot read them.

Private encryption is automatic and has no shared phrase. Public-key discovery is not independently authenticated, so an active controller can inject a future recipient key even though passive access to DATA_KEY cannot decrypt protected content.

Where it fits

Use public rooms for repository-aware conversation that needs ForkBot, MCP, or webhooks. Use private channels and direct messages when controller integrations are not required.
