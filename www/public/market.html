Build it once. Ship it to the mesh.

Extensions, 3D objects, avatars, worlds, audio, agents, services, and themes all travel as the same signed package. One format, one install lifecycle, one Library — instead of a separate store for every kind of thing people make. Everything below is open source, and the shelves are waiting for what you build.

Create a package Get the desktop app

You keep ownership

Every manifest carries its creator identity and states that the creator retains ownership. Distribution never becomes assignment.

Licence outlives the install

Your licence is recorded separately from installation state, so removing a package keeps the licence record and the attribution.

Nothing installs quietly

Permissions are declared in the manifest and shown before anything activates. Uninstalling stops work, detaches UI, and deletes package-owned data.

Moving to ForkMesh

Step-by-step guides for bringing a site's repository, reviews and deploys to ForkMesh while your current host keeps serving it. The desktop app's Market, Guides tab installs what each guide needs in one click.

Move a Cloudflare Pages site off GitHub

From Cloudflare Pages + GitHub

Your site deploys to Cloudflare Pages from a GitHub repository. Bring the repository, issues and deploys to ForkMesh; Cloudflare keeps serving the site and your domain does not change.

  1. In the ForkMesh desktop app open Market, then Guides, and choose Install what you need on this guide.
  2. On app.forkmesh.com open Repositories, choose New and pick GitHub as the source. Start resumable import brings issues, pull requests and history; Remote clone URL copies a public repository's code. For a private repository choose New repository and run git push --mirror to the address it shows.
  3. In Cloudflare create an API token with the Cloudflare Pages: Edit permission and note your account ID.
  4. In the desktop app open Settings, Secrets & Coves and add CLOUDFLARE_API_TOKEN, CLOUDFLARE_ACCOUNT_ID and FORKMESH_ACTIONS_ALLOW_NETWORK set to 1.
  5. Add .forkmesh/deploy.yml to the repository: on push to main, a job that runs your build (for example npm ci && npm run build) and then npx wrangler pages deploy dist --project-name=<your project>.
  6. In the Cloudflare dashboard open the Pages project, then Settings, Builds & deployments, and turn off automatic deployments from GitHub so only ForkMesh deploys.
  7. Push a commit and watch the run in Actions. Deploys that use secrets run on your ForkMesh desktop, so keep it signed in and online.
  8. Open Status Page settings and add a monitor for your site's address so you hear when it goes down.

Uses the Site Mover pack.

Create a package

A package is a folder. Four steps take it from an idea to something the client can install, and the whole envelope is small enough to read in one sitting.

  1. Lay out the folder

    A distributable .fmpkg is a ZIP-compatible archive with a fixed shape. Start it as a directory under marketplace/packages/<id>/ in your repository. 

    manifest.json     the identity, terms, entry points, permissions
content/          the creation itself — code, scene, model, audio, theme
preview/          how it looks and what it does, for the listing
LICENSE           the terms you are granting
SIGNATURE         signs the manifest and every file digest

  2. Write the manifest

    manifest.json is the contract: who made it, what it is, what it costs, what it may touch. It validates against manifest.schema.json, and the client refuses to list a package whose manifest does not validate. Copy this and edit it. 

    {
  "$schema": "../../manifest.schema.json",
  "schemaVersion": 1,
  "id": "my-package",
  "name": "My Package",
  "creator": {
    "id": "did:forkmesh:yourhandle",
    "handle": "yourhandle",
    "displayName": "Your Name",
    "verified": false
  },
  "type": "virtual.object",
  "category": "3D",
  "version": "1.0.0",
  "summary": "One sentence a stranger can understand.",
  "license": {
    "model": "free-open-source",
    "spdx": "MIT",
    "creatorRetainsOwnership": true
  },
  "price": { "amount": 0, "currency": "USD" },
  "entrypoints": {
    "world": "content/world/index.js",
    "settings": "builtin:package"
  },
  "permissions": [
    {
      "id": "world.socialfeed.read",
      "label": "Read the public feed snapshot supplied by the World",
      "risk": "low"
    }
  ],
  "screenshots": [
    { "path": "preview/market.png", "alt": "My Package in ForkMesh" }
  ],
  "trust": { "sourceAvailable": true, "signature": "required" },
  "install": { "bundled": false, "default": false },
  "lifecycle": { "migrations": [] }
}
    • Pick your terms. license.model accepts free-open-source, one-time, commercial, subscription, pay-what-you-want, limited-edition, free-with-paid-source, and revenue-share. creatorRetainsOwnership is always true — the schema will not let you sign that away. The Market does not take payments yet, so every package listed today is free.
    • Ask for the minimum. Every permission carries a label a person can read and a risk of low, sensitive, or high. They are shown before install, so vague or oversized requests cost you installs.
    • Credit what you build on. A dependency may carry revenueSharePercent, so a package built on someone else's work can declare the share it owes them.

  3. Build the thing, then make it removable

    Put the creation in content/ under the path your entry point names. Then walk the lifecycle backwards: an installer validates and activates, but it must also undo, so plan that half from the start.

    • Validate the manifest, signature, permissions, and content paths before activating anything.
    • Record the licence separately from install state.
    • Activate declared contributions only after install succeeds.
    • Every database change in lifecycle.migrations must name both an up and a distinct down SQL file. Uninstall runs the down files in reverse order inside host-owned transactions.
    • On removal: stop active work, detach every UI contribution, revoke runtime capability handles, and delete package-owned settings and cache. Output the user created and their licence records stay in the Library.

  4. Describe it honestly

    preview/ is what a stranger judges you on. Add current screenshots that show the contribution, then describe its actions, surfaces, and appearance in source. Market listings show those previews; marketplace clients still render the live installed contribution.

Publish it

Build one deterministic .fmpkg archive, publish it on any HTTPS host, and submit its digest below. Source catalogs may live on ForkMesh, a ForkMesh mirror, GitHub, GitLab, or any ordinary Git or HTTPS host; provider names are display hints, not installer logic.

  1. Sign the archive

    SIGNATURE signs the canonical manifest and the digest of every archived file. Mirrors carry the bytes, but they cannot silently swap the creator or the content. A marketplace must reject an external archive that omits the signature or whose file digests do not verify.

  2. Add it to the catalog

    Run marketctl pack, host the resulting archive and manifest, then submit their exact SHA-256 digests to the review queue. The approved catalog contains locations and digests only; third-party assets are never copied into ForkMesh core. Self-hosted markets use the same marketplace/catalog.json contract. 

    git clone https://forkmesh.com/forkmesh/forkmesh.git
cd forkmesh && mkdir -p marketplace/packages/my-package

  3. Watch it land on the shelf

    After five active members approve the exact manifest, a current owner of the linked forkmesh/forkmesh organization repository performs final approval. It then appears in the desktop Market and installs into the Library. Read the marketplace README for the full envelope and lifecycle contract, or the docs to get set up first.

Community review

Publication requires five distinct active members. No wallet, token, balance, or payment is needed to review, and reviewers are listed in approval order. The submitter cannot review their own package, and the final repository owner must be a different person who did not cast a member approval.

The rules

Short, and the same for everyone — including ForkMesh's own packages.

  • One format, every category

    Software, virtual goods, agents, services, and themes use the same envelope. A new category extends the schema; it never invents another installer or another store.

  • Creators retain ownership

    The manifest records the creator identity and asserts retained ownership. Bundled ForkMesh packages carry the same field as yours.

  • Install is reversible

    Built-ins are removable too. Capture ships enabled and can be removed and installed again from Market → Library without restarting ForkMesh.

  • Permissions are declared, not discovered

    What a package may touch is in the manifest, rated for risk, and shown before anything activates. Runtime capability handles are revoked on removal.

  • Signatures are the trust boundary

    Checked-in bundled sources inherit the signed release bundle's integrity. Anything exported as a downloadable .fmpkg must add a creator signature to be accepted.

The shelves are mostly empty. That is the opportunity.

The format is in use today and every category is open. Bring an extension, a world, an avatar, an agent, or a service — and keep what you make.
